# Arc model usage ledger: review candidate

## Scope and release status

This is a local implementation candidate. No production database migration, Edge Function deployment, billing change, provider call, or production quota activation is performed by these files.

- Luna is available to everyone with no ordinary allowance cap. Its separate `luna` pool records costs, and the database rejects enabling quota enforcement on that pool. Existing request-level safety/abuse guards remain necessary.
- Sol has a separate configurable `sol` allowance. Approved Free amounts are $0.05 per UTC day and $1 per UTC calendar month. The approved Boost amount is $6 per UTC calendar month with no additional daily cap.
- Astra has a separate `astra` allowance. The owner-approved current Boost amount is prepared as $3 per UTC calendar month; Free has a zero allowance behind the separate model entitlement gate. No additional daily Astra cap is invented.
- All pools, including Astra, start with enforcement disabled. Product entitlement and allowance enforcement are distinct. The ledger does not grant model access.
- `research`, `images`, `builder_images`, and `background` pools are available for additional cost observation. They do not replace existing feature limits or change their behavior. Their budgets are unconfigured. Voice is explicitly excluded from this work: no voice model, behavior, limit, UI, or shared allowance changes.
- Administrators are measured but quantity-uncapped. Actual `admin_users` and server `user_has_boost` determine tier; frontend caches, email lists, and user metadata are not trusted.

The SQL is staged at `supabase/migrations/20261010040518_arc_usage_ledger.sql`. Its filename was generated by official Supabase CLI 2.120.0 with `supabase migration new arc_usage_ledger`, using a temporary CLI home and no sign-in. The migration has not been applied to production.

Release order: apply this observation-only migration; deploy all covered provider entrypoints and durable-resume adapters; deploy the percentage-based UI; verify the available read-only/observation behavior and complete the release review; only then activate Sol and Astra together in an explicit transaction. Runtime admission sends new nonadmin premium requests to Luna with an update notice while their policy is off or unconfigured; the observation-only flag never grants uncapped premium access. Existing provider sessions remain on their actual model with a finite provider ceiling, and administrators remain metered. The activation is an operator release step, not automatic migration behavior. Do not enable any other pool or change voice. No paid model calls are required by the SQL tests. Live provider-path verification must not be claimed from local fixtures. See `docs/GPT_MODEL_LINEUP.md` for per-stage rollback and artifact verification.

## Accounting contract

`arcUsageAccounting.ts` prices integer USD nanodollars (`$1 = 1,000,000,000`). Standard rates per token:

| Actual model | Uncached input | Cached input | Cache writes | Output including reasoning |
| --- | ---: | ---: | ---: | ---: |
| GPT 6 Luna | 100 | 10 | 125 | 500 |
| GPT 6.1 Sol | 2,000 | 100 | 2,500 | 10,000 |
| GPT 6 Astra | 10,000 | 1,000 | 12,500 | 50,000 |

Source pages: [Luna](https://developers.openai.com/api/docs/models/gpt-6-luna), [Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [Astra](https://developers.openai.com/api/docs/models/gpt-6-astra), verified October 10, 2026. These are provider-cost rates, not user payment balances or a per-message price.

- Non-cached input/output for Sol is 20x Luna and Astra is 100x. Cached Sol input is 10x Luna, so a universal 20x message multiplier is not accurate accounting.
- Cache read/write token counts are disjoint subsets of total input. Cache-write cost replaces the ordinary input rate for those tokens.
- More than 272,000 input tokens triggers 2x all input/cache rates and 1.5x all output rates for the request. Reasoning tokens already included in output must not be added twice.
- This threshold is per actual request. Pass `{aggregation:'session'}` for cumulative Agents-session usage; if aggregate input crosses 272K, the result is labeled `conservative-session-detail` because many short requests do not establish long context. Precise reconciliation needs request-level data or authoritative provider accounting.
- Agents usage does not report cache-write counts and remains best-effort: counts can change after a session completes. When session write detail is missing or null, price every non-cached input token at the higher cache-write rate and label the result `conservative-session-detail`, even below 272K. `cacheWriteTokensEstimated: true` explicitly marks the assumed write count rather than presenting it as provider data. This can overestimate that input component by up to 25% at the same context tier; cached reads and output retain their reported categories. An explicit write count, including zero, is honored. See [Agents observability and usage](https://developers.openai.com/api/docs/guides/agents-api/observability), verified October 10, 2026. Session completion is not an authoritative invoice; later corrections need the revision-fenced reconciliation path, not repeated final settlement.
- Missing usage returns `null`, not zero. A provider that reports only total tokens produces an explicitly conservative estimate using the maximum applicable output rate. It is not an invoice or a fabricated input/output split.
- Whole-cent provider spend-control limits are distinct from precise usage debits. A sub-cent Luna turn must not be rounded to zero or billed as a whole cent.

`arcUsageLedger.ts` exports:

1. `reserveArcUsage(db, {userId, requestId, attemptId, source, model, reserveNanos, fingerprint, pool?, minimumReserveNanos?, clampToRemaining?})`. It infers Luna/Sol/Astra's pool from the actual model. For an Agents session, use a minimum of 10,000,000 nanos and allow clamping. The result contains `allowed`, `reservationId`, `replayed`, `state`, `revision`, `cumulativeCostNanos`, `reservedNanos`, `providerBudgetCents`, and the allowance snapshot.
2. `recordArcUsage(db, {userId, reservationId, receiptId, cumulativeCostNanos, final, usage?})`. A non-final checkpoint advances a conservative high-water mark. A final, known usage value can replace a provisional estimate with a lower precise amount and release its unused hold.
3. `releaseArcUsage(db, {userId, reservationId, receiptId, reason})`. Only for confirmed no-provider/no-spend outcomes. Interrupted or ambiguous provider submission is not a reason to refund.
4. `reconcileArcUsage(db, {userId, reservationId, receiptId, expectedRevision, authoritativeCostNanos, reason, usage?})`. Correct a settled estimate with authoritative evidence. A revision fence prevents concurrent corrections overwriting one another.

Only accounting facts, token counts, rate versions, and concise reconciliation explanations belong in `usage`; never pass whole model responses, prompts, tool results, credentials, or personal content.

## Identity, concurrency, and failure rules

- A logical request has an account-scoped stable `requestId`. Every distinct paid provider attempt/session has its own stable `attemptId`. Tool rounds inside one cumulative Agents session are checkpoints on that same attempt, not repeated fixed charges.
- Bind attempts to a server-derived request fingerprint and actual model. Reusing an identity with changed model/fingerprint/source fails.
- `replayed` does not authorize a second provider POST. Resume a known provider session or return the known result. Keep an ambiguous first POST held for reconciliation. Existing durable intent/lease safeguards must be preserved.
- Reserve before provider work. Reserve a larger absolute ceiling on the same attempt before increasing an existing provider budget. The provider call is outside the database transaction.
- One short account/pool advisory transaction lock serializes reservation, settlement, and reconciliation. Both daily and monthly aggregates include in-flight holds. Independent model pools cannot spend one another's allowance.
- Checkpoints use cumulative amounts, never sum raw cumulative provider totals repeatedly. Receipt keys are idempotent and reject changed receipt data.
- A final receipt releases unused held cost. Stale checkpoints after final settlement are ignored. Replaying/top-upping a settled attempt cannot revive its hold.
- Recorded real cost is never discarded because it exceeds the estimate. The ledger can record overshoot and denies subsequent admission under the applicable limit. This does not promise that best-effort provider spend control is a hard financial guarantee.
- Periods are pinned when the first attempt is admitted. Late settlement updates its original UTC day/month, not a new period. A denied first attempt does not pin a request to a spent old period. Tier changes reuse the same consumption, rather than resetting balances.
- Unknown outcomes retain reservations. No timed unconditional refund job is installed.

## Read-only UI

`get_my_arc_usage({pool_name:'sol'})`, or `pool_name:'astra'`, reads only the authenticated caller. The default pool is Sol. It returns:

- `pool`, `tier`, `enforcementEnabled`, `configured`, `adminUncapped`
- `daily` and `monthly`: `spentNanos`, `reservedNanos`, `limitNanos`, `remainingNanos`, `usagePercent`, `resetsAt`

Off/unconfigured policies have null visible limits/percentages. Admin limits are null. A monthly-only policy has a null daily percentage. Render percentages and reset time, not raw dollar amounts. Do not show a quota meter for unlimited Luna. Existing image, voice, and research meters retain their own policies.

## Verified baseline and coverage

At source commit `e562f1fdc5f1a729d083b3b95d5a190c9efc4f63`, ordinary GPT/Think had no finite account allowance: `useSubscription.tsx` used Infinity/no-op counting. The 20-per-day ledger applied to Flash, not Luna or a shared GPT token budget. Existing durable guards are 64,000 total tokens for Work, 512,000 for App, 16 turns, 20 minutes, and a four-active-Work-request pressure guard. They are per-run safety limits, not account quotas.

Integration must cover ordinary Chat, streaming/Agents paths, all paid retries and fallbacks, durable Work/Git/App resumes, document/image analysis, file generation, and other premium-model calls outside voice. Ordinary background/title/memory/helper costs use Luna's observation pool; they must not consume a Sol or Astra allowance merely because a chat selected that model. Voice calls and voice tool delegation are completely excluded; no new ledger dependency may affect them. Research/image provider bills remain separate from associated Luna synthesis calls.

Historical accounting does not contain trustworthy input/output/cache/reasoning detail for ordinary chat. Existing `cloud_runs.checkpoint.engine.tokens` is total-only run telemetry, not a complete invoice. Do not claim exact historical cost from saved message counts or visible text length.

## Validation

- `deno test supabase/functions/_shared/arcUsageAccounting_test.ts supabase/functions/_shared/arcUsageLedger_test.ts`: 15 passing tests, including missing/null/explicit-zero cache-write detail, sub-threshold conservative session pricing, and long-session uncertainty.
- `node scripts/test-arc-usage-ledger.mjs`: passes against isolated PGlite PostgreSQL. Covers observation defaults, Luna unlimited, separate/monthly-only Astra, exact allowance allocation, replay conflicts, cumulative high-water marks, final refunds, overshoot capture, owner/grant checks, admin metering, revision fencing, and UTC rollover.
- `node scripts/test-arc-usage-native-sql.mjs`: passes with official PostgreSQL 17.11 in socket-free single-backend mode. Compiles the entire generated migration and checks observation defaults, reservation, cumulative checkpoint, lower exact final/refund, replay, exact quota, overage capture, and unlimited Luna. The temporary database is deleted. This is native SQL execution, not a simultaneous-connection test.
- `node scripts/test-arc-usage-concurrency.mjs`: prepared but not run successfully. With explicit owner approval, official Debian PostgreSQL 17.11 packages were downloaded and needed binaries/libraries extracted under `/tmp`, without system installation or service changes. Both normal and approved elevated execution were blocked when PostgreSQL tried to create its local Unix socket (`Operation not permitted`). Failed fixture clusters were deleted. This script provisions only a disposable Unix-socket-only local cluster and is ready to test true parallel duplicate/competing reservations, final/checkpoint/top-up races, receipt replay, and reconciliation races in an environment permitting local sockets.

PGlite serializes its connection. Its behavior tests are not a substitute for the native multi-connection concurrency release check. Provider-budget semantics, runtime integration, complete application checks, and production verification belong to the release owner.
